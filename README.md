# FLOW LAB — 길을 고치는 사람

끊어진 시골길부터 꽉 막힌 도심까지, 도로를 직접 고쳐 차를 흐르게 하는 설계 퍼즐입니다.
죽는(Game Over) 구조는 없습니다. **지켜보고 → 고치고 → 다시 돌려 봅니다.**
고칠 때는 위에서 내려다보는 흑백 화면에 도로와 내가 놓은 것만 컬러로 보이고, 실행하면 컬러로 바뀌며 대각선 시점으로 흐름을 보여 줍니다.
현장 주임 펭귄 "핍"이 처음부터 차근차근 안내합니다.

## 실행

`index.html` 을 브라우저로 열면 됩니다(설치·빌드 없음). PC와 모바일(터치) 모두 됩니다.
WebGL 이 안 되는 환경에서는 2D 지도로 대체됩니다.

## 스테이지

쉬운 것부터 시작하고, 도구는 스테이지가 올라갈 때마다 조금씩 풀립니다. 앞 스테이지에서 별을 하나 받으면 다음이 열립니다.

| | 스테이지 | 배경 | 쓸 수 있는 도구 | 할 일 |
|---|---|---|---|---|
| 1 | 끊어진 시골길 | 밭·풍차·경운기가 있는 시골 | 도로, 철거 | 마을에서 장터까지 길을 잇는다 (튜토리얼) |
| 2 | 등굣길 횡단보도 | 강변 읍내 | + 다리, 육교 | 횡단보도 앞 정체를 푼다 |
| 3 | 도심 지름길의 역설 | 강변 도심 | 전부 (15종), 잠긴 도로 등장 | 지름길로 몰리는 차를 나눈다 (브라에스 역설) |
| 4·5 | 항구 도시, 산길 | | | 준비 중 |

별은 위에서부터 순서대로 받습니다. 예) 3스테이지: 30초 이하 → 사고 없이 → 20초 이하 → (보라색) 17초 이하를 $1.2M 안에서.

공식 시드(1225) 측정값:

| 스테이지 | 설계 | 예산 | 평균 이동시간 | 사고 | 별 |
|---|---|---|---|---|---|
| 1 | 가장 짧게 9칸 잇기 | $900K | 19.6초 | 0 | ★★★ |
| 1 | 돌아서 12칸 | $1.2M | 19.3초 | 0 | ★★ |
| 2 | 고치기 전 | $0 | 47.1초 | 0 | – |

수치는 시드에 따라 달라집니다(3스테이지 통행 차단은 다른 시드에서 사고가 2~3건 나기도 합니다).

## 조작

| | PC | 모바일 |
|---|---|---|
| 설치 | 칸 클릭·드래그 | 칸 탭·드래그 |
| 실행 / 정지 | `Space` 또는 ▶ | ▶ |
| 되돌리기 | `Ctrl+Z` | ↶ |
| 시점 회전 (실행 중) | 드래그 | 한 손가락 드래그 |
| 확대 | 휠 (커서가 가리키는 곳으로) | 두 손가락 (손가락 사이로) |

도구 아이콘은 누르면 선택만 되고, 손가락(또는 마우스)을 올리고 있는 동안에만 이름·가격·설명이 보입니다.
핍의 그림 설명은 화면 오른쪽의 `?` 목록에서 고릅니다. 스테이지가 올라가 도구가 풀리면 목록도 늘어나고, 아직 안 들은 항목에는 점이 붙습니다.
휴대폰 세로 화면에서는 지도가 90° 돌아가 출발지가 아래, 도착지가 위로 옵니다.

## 고쳐 쓰기 쉬운 파일

- `js/script.js` — 핍의 대사 전부. 따옴표 안의 글만 고치면 됩니다.
- `js/stages.js` — 스테이지별 맵(12×8 글자 그림), 교통량, 예산, 도구, 목표.

## 엔진 (`js/sim.js`)

- **길 찾기**: A*, 간선 비용은 BPR 함수 `t = t₀·(1 + α·(v/c)^β)` (α=0.15, β=4). 차량은 약 3초마다 경로를 다시 찾습니다.
- **앞차 따라가기**: `v* = v_max·max(0, (Δx − d_min)/d_safe)` 에 제동 한계와 반응 지연을 더한 모델.
- **운전자**: 스테이지마다 구성이 다릅니다. 도심은 일반 70% / 과속 15% / 초보 15% + 버스(승객 20명), 시골은 승용차·경운기·오토바이. 차량마다 `(v₀, T, a, b)` 가 정규분포 난수.
- **사고**: 차체가 실제로 겹치면 사고. 그 칸은 10초간 통행 불가, 사고 차량은 30초 페널티.
- **평가**: `T̄ = Σ Wᵢ·tᵢ / Σ Wᵢ` (승용차 W=1, 버스 W=20). 도착하지 못한 차량도 포함합니다.
- 엔진은 칸의 속성에 따른 국소 규칙만 계산하며 특정 좌표를 채점하지 않습니다. DOM 의존성이 없어 Node 에서도 돌아갑니다.

```js
const F = require('./js/sim.js');
const tiles = F.parseStage(F.STAGE1);
tiles[4 * F.W + 5].barricade = true;          // 지름길 (5,4) 차단
console.log(new F.Sim(tiles, { seed: 1225 }).run());
```

## 시작 화면과 튜토리얼

처음 열면 표지판 모양의 시작 화면이 뜨고(핍은 여기엔 나오지 않습니다), **출근하기**를 누르면 현장 주임 핍(안전모와 안전조끼를 걸친 펭귄)이 "관리자님!" 하고 찾아다니다가 1스테이지 시골길을 함께 잇습니다.
튜토리얼은 짧습니다: 도구함 → 도로 고르기 → 끊어진 길 잇기 → ▶ 실행 → 결과표 → 인수인계서. 2·3스테이지에 처음 들어가면 핍이 새 도구와 힌트를 두세 마디로 알려 줍니다.

나머지는 궁금할 때 물어봅니다. 도구를 누르면 뜨는 풍선의 **핍에게 물어보기**, 또는 `?` 창의 목록에서 주제를 고르면 핍이 발표봉과 자료판을 들고 나옵니다. 자료판의 예시는 사진이 아니라 게임의 2D 도면 렌더러가 그 자리에서 그리는 작은 장면이라 차가 실제로 움직입니다(`js/lecture.js`).

**핍의 대사는 전부 `js/script.js` 한 파일에 있습니다.** 따옴표 안의 글만 고치면 게임에 그대로 반영됩니다. `{play}`, `{t:road}` 같은 표시는 버튼 그림으로 바뀝니다(파일 맨 위에 목록이 있습니다).

핍은 그림 파일이 아닙니다. `js/penguin.js` 가 로우폴리 3D 모델을 포즈별로 한 장씩 렌더링한 뒤 흰 테두리와 그림자를 둘러 오려 낸 사진처럼 만듭니다. WebGL 이 없으면 글만 나옵니다.

## 동네

- 격자 안은 큰 건물 몇 동, 주택(단독·연립·차고 딸린 집), 공원, 그리고 길을 낼 수 있는 빈 터로 이루어집니다. 빈 터는 풀밭·꽃밭·텃밭·자갈 주차장으로 보이고, 길을 내면 사라집니다.
- 강을 건너는 기존 도로는 석조 교대에 주철 아치와 난간이 달린 다리입니다. 강 위에 새 길을 내려면 다리 도구를 써야 합니다.
- 육교는 상판·계단·난간이 하나로 이어진 구조물이고, 사람들이 실제로 계단을 올라 건너갑니다.
- 보도에는 사람들이 오가고, 몇몇은 강아지를 산책시킵니다. 강에는 배가 지나갑니다. 모두 배경이며 교통 시뮬레이션에는 영향을 주지 않습니다.
- 격자 밖은 저주파 노이즈로 녹지 / 주택가 / 상가를 나눠 배치합니다. 움직이지 않는 것은 재질별로 한 덩어리로 합쳐 그립니다.

## 디자인

도로 표지판에서 가져온 시각 언어를 씁니다: 차선 점선이 들어간 아스팔트색 상단 바, 초록 방향 표지판 모양의 예산판. 상자는 예산판·도구 트레이·상태 띠·창에만 쓰고 나머지는 글자와 아이콘만 둡니다. 글꼴은 쓰임새에 따라 셋입니다: 표지판·제목은 도현, 숫자·금액은 Barlow Condensed, 본문은 Wanted Sans. 아이콘은 이모지 없이 직접 그린 SVG입니다.

## 알려진 한계

- 신호등, 가변 차선, 방지턱은 단독으로는 효과가 작습니다.
- 교차로를 바짝 붙여 지으면 드물게 정체가 오래 풀리지 않을 수 있습니다.
- 4·5스테이지(항구 도시, 산길)는 이름만 있습니다.
- 보행자가 길을 건너지 못해 생기는 문제(횡단보도를 없애면 사람이 고립되는 식)는 아직 규칙에 없습니다.
- 격자 바깥의 동네와 그 도로를 달리는 차, 보행자, 배는 배경이며 시뮬레이션에 포함되지 않습니다.
- 격자 안 보행자는 곧게 뻗은 보도 구간만 오갑니다. 바깥 보행자는 길을 따라 지나갑니다. 목적지를 정해 경로를 찾아가지는 않습니다.
