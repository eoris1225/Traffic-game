# FLOW LAB — 교통 체증 해결 시뮬레이션 퍼즐

죽는(Game Over) 구조 없이 **[문제 관찰] → [도로 설계] → [재실행·검증]** 으로 진행하는 도로망 설계 퍼즐입니다.
설계는 2D 도면에서 하고, 실행하면 로우폴리 3D 디오라마로 차량 흐름을 봅니다.

## 실행

`index.html` 을 브라우저로 열면 됩니다(설치·빌드 없음). 3D 화면은 `vendor/three.min.js`(MIT)를 쓰며,
WebGL 이 안 되는 환경에서는 자동으로 2D 화면으로 실행됩니다.

## 플레이 방법

1. **개선 전 관찰** — 기존 도로망에서 정체와 사고가 나는 모습이 재생되고, 대조군 기록이 남습니다.
2. **설계** — 총예산 $3,500 안에서 15가지 도구를 아무 타일에나 자유롭게 설치합니다. 정답 좌표는 없습니다.
3. **재실행** — 같은 수요(같은 차량·같은 출발 시각)로 다시 돌려 개선 전과 비교합니다.

목표: **인당 평균 통행시간 30초 이하 · 사고 1건 이하**. 등급은 S(16초 이하·무사고) / A(23초 이하·무사고) / B.

| 조작 | 동작 |
|---|---|
| 타일 클릭·드래그 | 선택한 도구 설치 (같은 도구로 다시 클릭하면 회수) |
| `Ctrl+Z` | 되돌리기 |
| `Space` | 일시정지 |
| `V` | 실행 화면 3D ↔ 2D 분석 지도 전환 |
| 실행 중 드래그 / 휠 | 3D 시점 회전 / 확대 |
| 실행 중 차량 클릭 | 그 차량의 A* 경로 추적 |

## 도구

| 분류 | 도구 | 엔진에서의 효과 |
|---|---|---|
| 도로/확장 | 일반 도로 $100, 차선 확장 $250, 일방통행 $100, 철거 $50 | 그래프 간선 추가·제거, 차로 수(용량 c) 변경, 방향 그래프화 |
| 차선/유도 | 색깔 유도선 $100, 버스 전용차선 $150, 가변 차선 $200 | 초보 운전자 지연 τ·오류 P_err ×0.2, 버스(W=20) 전용 차로, 교통량 비율 Φ 에 따른 중앙 차로 방향 전환 |
| 교차/입체 | 회전교차로 $500, 신호등 $300, 고가 다리 $700, 지하차도 $800, 육교 $400 | 양보 합류, 축별 감응 신호, z=±1 레이어 분리, 횡단보도 정지 제거 |
| 안전/통제 | 과속카메라 $400, 과속방지턱 $100, 바리케이드 $100 | 반경 내 과속 차량만 감속, 전 차량 감속, 타일 폐쇄(Cost=∞) |

잠금 도로(붉은 테두리)는 철거·확장할 수 없지만 노면 표시와 시설물은 설치할 수 있습니다.

## 엔진 모델 (`js/sim.js`)

- **경로 탐색**: A*, 간선 비용은 BPR 함수 `t = t₀·(1 + α·(v/c)^β)`, α=0.15, β=4. `v` 는 그 간선 위의 현재 차량 수이고 차량은 약 2.5~3.5초마다 경로를 다시 찾습니다.
- **차량 추종**: `v* = v_max·max(0, (Δx − d_min)/d_safe)` 에 제동 한계와 반응 지연 τ 를 더한 모델.
- **이질적 에이전트**: 일반 70% / 과속 15% / 초보 15% + 버스. 차량마다 `(v₀, T, a, b)` 를 정규분포 난수로 받습니다.
- **사고**: 차체가 실제로 겹치면 사고로 판정하고 TTC 를 기록합니다. 사고 타일은 10초간 통행 불능, 사고 차량은 통행시간에 30초 페널티.
- **평가 지표**: `T̄ = Σ Wᵢ·tᵢ / Σ Wᵢ` (승용차 W=1, 버스 W=20). 도착하지 못한 차량과 출발 대기 차량도 포함합니다.
- 엔진은 타일 속성에 따른 국소 규칙만 계산하며, 특정 좌표를 채점하는 코드는 없습니다. DOM 의존성이 없어 Node 에서도 돌아갑니다.

```js
const F = require('./js/sim.js');
const tiles = F.parseStage(F.STAGE1);
tiles[4 * F.W + 6].round = true;              // (6,4) 에 회전교차로
console.log(new F.Sim(tiles, { seed: 1225 }).run());
```

## 측정 결과 (공식 시드 1225)

| 설계 | 예산 | 인당 평균 통행시간 | 사고 | 도착 |
|---|---|---|---|---|
| 개선 전 | $0 | 43.5초 | 3건 | 62/111 |
| ① 회전교차로 2곳 + 유도선 | $1,200 | 23.8초 | 1건 | 106/111 |
| ② 회전교차로 3곳 + 육교 2 + 유도선 + 카메라 2 | $3,400 | 21.6초 | 0건 | 109/111 |
| ③ 북쪽 고가 다리 + 회전교차로 3곳 | $3,000 | 11.1초 | 0건 | 111/111 |

시드가 달라지면 수치도 달라집니다(예: 시드 7 에서 ①은 22.7초·사고 4건). 화면의 "내비게이션 예측"은 일부러 다른 시드로 계산한 추정치입니다.

### 알려진 한계

- **브라에스의 역설은 현재 수치에서 재현되지 않습니다.** 지름길을 바리케이드로 막는 것만으로는 43.5초 → 42.5초로 거의 변화가 없고, 회전교차로 2곳과 함께 쓰면 오히려 막지 않은 쪽이 빠릅니다(23.8초 대 28.0초). 바리케이드 도구는 실험용으로 남겨 두었습니다.
- 신호등, 가변 차선, 과속방지턱은 단독으로 쓰면 통행시간 개선이 작거나 없습니다.
- 드물게 교차로가 가까이 붙은 설계에서 장시간 정체가 풀리지 않을 수 있습니다.
- Stage 2~5 는 잠금 표시만 있고 구현되어 있지 않습니다.
